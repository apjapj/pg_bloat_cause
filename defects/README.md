# defects: the defects this extension has had, and the test that must still catch each one

A bug fixed today can be reintroduced tomorrow by a refactor, and nothing notices unless something
puts it back. This directory records the extension's real defects, one pair of files each, and
`scripts/check-defects.sh` re-injects every one and requires the test that first caught it to fail
again. The number it prints is a regression rate, not a one-time red-first step: of the defects the
suite once caught, how many does it still catch.

It complements the "Proving a check fails" rule in `CONTRIBUTING.md`. That rule is done once, by
hand, when a check is written. This runs the same idea on every recorded defect, on demand, and says
so out loud when one stops being caught.

## The two files

- `<id>.patch` is a unified diff. Applied to this tree with `git apply`, it reintroduces the defect.
  It is generated by reverting the fix, so it stays exact rather than paraphrased.
- `<id>.meta` is `key=value` lines:

  | key | what it holds |
  | :-- | :-- |
  | `id` | the identifier, matching the file name |
  | `class` | what kind of defect it was |
  | `found` | when and where it was found |
  | `fixed` | the release that fixed it |
  | `test` | the test file that must fail while the defect is present |
  | `detail` | one sentence on the defect |

## Running it

```
make defects PG=18        # or ./scripts/check-defects.sh 18
```

It builds the CI server image, installs the pristine extension, then for each defect copies the
patched release script into the server, runs the named test, and requires it to fail. The summary is
`caught/(caught + missed)`; a `could-not-run` cell (the patch did not apply, or the test did not
report a failing assertion) is reported and is never counted as caught. Exit status is 1 when any
defect is missed, so it can be a CI step.

The named test is a pgTAP file, run with `pg_prove`. A defect whose only catcher is a scenario needs
a pgTAP assertion that catches it too, or the record points at a test that cannot fail: a recorded
defect with no test that fails while it is applied is not recorded, it is forgotten.

## Adding one

Fix the bug and keep the test that caught it. Then save the reverse of the fix as `<id>.patch`
(`git diff -R` over the fix, or revert the change and diff), and record the metadata.
